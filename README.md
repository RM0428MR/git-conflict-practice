# はじめてのコンフリクト解消 ☕

カフェの営業時間を題材に、GitHubのPRでコンフリクトを解消する練習です。
目安は10〜15分。プログラミングや環境構築は不要です。

## 始める前に

講師にGitHubへの登録とPRの準備をしてもらってください。
研修生には、このリポジトリの書き込み権限とGitHubアカウントが必要です。
今回はGitHubのブラウザ画面だけで取り組めます。

## 今回の依頼

[cafe.md](cafe.md) の営業時間について、2人が別々に変更しました。

| ブランチ | 依頼 |
| --- | --- |
| `practice/early-opening` | 朝のお客様向けに、開店を10時から9時にする |
| `practice/late-closing` | 仕事帰りのお客様向けに、閉店を18時から20時にする |

講師が開店時刻の変更を先に `main` へマージしています。
あなたは閉店時刻のPRを担当します。**両方の依頼を満たす営業時間**にしてください。

## やってみよう

1. Pull requestsから、閉店時刻の変更PRを開きます。
2. Files changedで変更意図を確認します。
3. Conversationへ戻り、競合の表示と **Resolve conflicts** を探します。
4. 次の記号に囲まれた2つの営業時間を読み比べます。

   ```text
   <<<<<<< practice/late-closing
   （このブランチの内容）
   =======
   （mainの内容）
   >>>>>>> main
   ```

5. 両方の依頼を満たす営業時間を1行にまとめ、上記の記号と不要な行を消します。他の行は変更しません。
6. **Mark as resolved** → **Commit merge** を押します。
7. Files changedで、更新後のmainに対して閉店時刻の変更だけが残っていることを確認します。
8. 講師に見てもらい、**Merge pull request** → **Confirm merge** で完了です。

`Commit merge` は作業ブランチに解消結果を保存する操作です。
`main` へ取り込むには、その後のPRのマージまで行います。
ボタンを操作できない場合は講師に権限・ルール設定を確認してもらってください。

## 完了チェック

- [ ] mainの営業時間が、朝と夜の両方の依頼を満たしている
- [ ] 営業時間が重複せず、1行になっている
- [ ] コンフリクトの記号が残っていない
- [ ] 定休日・おすすめメニューを変更していない
- [ ] PRがMergedになっている

## 振り返り

- なぜこの競合が起きたのでしょう？
- 片方の内容だけを残すと、どの依頼が失われますか？
- コンフリクトの解消と、PRのマージはどう違いましたか？
